# R07-05–R07-07 — Combined coverage, report workflows and calibration patch

Prepared 29 September 2026. Apply to `release/0.7.0` at
`665cdf7970e5bb8a1d0b923f9a6beb24d6e3bd91` (merged R07-04).

This is one reviewable patch and release candidate. R07-03 SNR improvements remain
scheduled after it. No package version or dependency changes are required; schema
7 gains optional evidence fields so earlier schema-7 reports remain readable.

## 1. Result and release boundary

The patch makes evaluated coverage explicit, localizes supported findings, adds
saved-report workflows, and requires accepted matching validation before a
statistical finding can block an episode. These three slices share one assembly
path: compute metrics → classify availability → assemble coverage → resolve
calibration → decide eligibility once → render all surfaces.

Default behavior changes: a critical statistical finding without matching accepted
validation becomes `review`, and readiness remains undefined. Deterministic contract
violations can still block. The default CLI gate remains `blocked,unknown`; review
is permitted by that gate. Unattended training should use
`--fail-on blocked,review,unknown`.

This implements enforcement infrastructure. It does not establish detector accuracy,
ship accepted production manifests, evaluate video quality or behavioral diversity,
or claim training success. Public-data re-audits and scientific validation remain
release work. Benchmark defect injection is diagnostic evidence, never acceptance.

## 2. Decisions tied to practical use cases

| Use case | Behavior in this patch | Why it matters |
| --- | --- | --- |
| 50 episodes have 14 torque channels each and 28 position/action channels | Torque has 700 computed / 700 eligible channel-episodes; 1,400 other subjects are excluded as inapplicable | Report-only torque measurements count as work done; unrelated channels do not dilute coverage |
| A channel's meaning is unresolved | Taxonomy-dependent checks remain unavailable and eligible | Uncertainty cannot improve the coverage denominator |
| Metadata tier skips motor payloads | Declared channels remain visible as skipped; required numeric evidence is unknown | A fast scan cannot appear to be a full numeric audit |
| Cameras exist but no visual runner executes | Camera stream-episodes are disclosed; decoded frames examined is zero and eligible frame count unknown | Numeric quality does not certify images |
| An operator requires capture timing | Every stream must compute the three acquisition checks; origin evidence alone is insufficient | A capture label cannot hide unusable timestamps |
| A motor holds still across a null value | The null breaks flatline adjacency; source-row intervals identify actual observed runs | Missing samples do not create a fabricated uninterrupted defect |
| A spike occurs at source row 500 | Defect support is `[500,501)` and wider filter support is recorded | Reviewers can inspect context without treating every filter sample as defective |
| The same warning appears throughout a task | Groups summarize metric, role, consequence, adapter and tasks, retaining member IDs | Prevalence aids review without automatically exempting findings |
| Thresholds or channel bindings change after validation | The manifest no longer matches; the candidate becomes review | Evidence for one interpretation cannot authorize another |
| A saved report lacks a source byte identity | Comparison lists available differences and explains why numeric readiness comparison is refused | Missing identity is not treated as proof of unchanged input |
| A metric or payload reader raises an exception | Coverage records errors; run becomes partial and CLI exits 2 after saving the available report | A software failure cannot become a clean audit |

## 3. Coverage contract (R07-05)

`Report.coverage`, `episodes[].coverage` and `streams[].coverage` record outcomes
separately from metric severity. Rows contain a key, unit, count per state, eligible
count, and reason histogram.

```text
eligible = computed + unavailable + skipped + error
```

`not_applicable` and `not_required` are excluded. `computed` means a finite result
was actually produced; a report-only measurement still counts. A known nonmatching
taxonomy is inapplicable; an unmapped taxonomy is unavailable. No-result, missing
input, skipped work and operational failure are distinct outcomes.

Metric units are channel-episode, stream-episode or episode. Required capabilities
use episodes. Separate dimensions report semantic mapping, capture-origin evidence,
visual quality and behavioral diversity. Mapping counts resolved semantics, not
validated physical units. Capture-origin counts producer provenance, not measured
clock usability. Visual coverage uses discovered camera stream-episodes; it never
invents a decoded-frame denominator. Training-window coverage remains unknown.

Counts cover loaded subjects only. Known unassessed episodes, refused sources and
inventory completeness are disclosed separately. The model rejects nonreconciling
counts and contradictory top-level aggregation. `gate.coverage` remains the legacy
graded-check summary and is not the new measurement ledger.

Requirements can name `required_metrics` such as `integrity.missing_pct` or
`motion.p99_torque`. A required metric must compute on all eligible subjects, with
at least one eligible subject. Missing metric names, zero applicable subjects or
incomplete evaluation produce unknown. This is an evaluation requirement; it does
not give the metric a threshold or require a favorable measured value.

## 4. Localized evidence and review groups

Intervals are zero-based, half-open source-row addresses. Flatline runs break on
null, NaN and infinity. An explicit row map restores transformed input to source
order; absent such a map, localization-dependent checks abstain. Gaps in source
addresses split serialized intervals. A flatline duration is only expressed in
seconds when the time unit is established and the run's axis is finite/increasing.

Spikes retain the existing 51-sample centered detector and record its wider support
interval. The enclosing filter interval may include source rows absent from a
partitioned view; it is a context bound, not a claim every row was consumed.
SNR and spectral results remain whole-episode. No sample deletion or repair is
performed. R07-03's SNR algorithm is unchanged.

Finding IDs identify metric + episode + source subject, using source channel indices
where available. They are not hashes of waveform contents or globally portable IDs
across renamed recordings. Source path/field/index, subject level, evidence strength,
consequence, support and calibration outcome remain in JSON. Duplicate IDs fail
report validation. Groups retain raw member IDs; terminal previews can truncate
locations explicitly, while inspection and JSON retain full evidence.

## 5. Report workflows (R07-06)

```bash
kalanos profiles list
kalanos profiles show numeric-core-v1
kalanos profiles show vision-imitation-v1
kalanos profiles validate acquisition.yaml
kalanos grade ./recording --profile acquisition.yaml --report audit.json
kalanos inspect audit.json --episode 'recording::episode_000000'
kalanos grade ./recording --hash-source --report audit-identified.json
kalanos compare previous-identified.json audit-identified.json --report comparison.json
```

See [profile examples](PROFILES.md). Profile validation checks structure and a
referenced policy; only grading can check actual dataset bindings and coverage.
Vision requirements intentionally remain unknown until a visual runner is available.

Comparison aligns exact episode and metric addresses, lists additions/removals,
measurement differences and changed identities. It requires compatible complete
source identity, configuration, scope, built-in implementation/runtime identity and
completed inventory. Unknown plugin implementation identities refuse numeric
comparison. A changed calibration outcome also invalidates readiness comparison.
It never attributes a metric change to a cause merely because a configuration
changed. Taxonomy remapping may appear as removed/added metric addresses; no fuzzy
matching is attempted. `readiness_delta` exists only when both scores are defined
and the reports are comparable. Comparability is an identity check, not a promise
that an undefined score can be compared.

`compare` exits 0 when comparable, 1 when incomparable, and 2 on invalid input or
an operational error. Its output cannot overwrite either input report. Python
entry points are `kalanos.compare` and `kalanos.load_report` (also in `kalanos.api`).

Optional `--hash-source` / `hash_source=True` computes complete local byte identity
before and after analysis. Canonicalization is sorted relative paths plus content
SHA-256 digests; symlinks, special files and nonlocal roots are refused. This reads
all regular files twice, even at metadata tier. Keep report outputs outside the
input root. A detected change withholds the report. This is a before/after
stability check, not an atomic filesystem snapshot. Without the option, ordinary
source evidence remains incomplete and numeric comparison may be refused.

Historical schema-6 reports remain historical; the loader does not manufacture
schema-7 decisions. A trimmed real schema-6.3 report is included as a compatibility
fixture with documented provenance, not as a new dataset evaluation.

## 6. Calibration contract (R07-07)

`calibration_manifests` is a list in a decision policy. `enforce_calibration` is
always true; false is rejected. The old `calibrated_metrics` field stays readable
but cannot authorize blocking. Policy YAML rejects duplicate keys and unknown
policy fields rather than silently accepting misspelled enforcement settings.

Each candidate finding records `calibration.context`, including all expected
identities. An accepted manifest must match:

- Metric ID and taxonomy type.
- Detector implementation and numerical runtime digest.
- Complete metric-policy thresholds/limits digest.
- Effective binding digest after configuration resolution.
- Scope digest covering requirements, execution, dictionary, declared evaluation
  scope, adapter versions and decision policy (excluding manifest contents and the
  deprecated name list to avoid self-reference).

The implementation hash conservatively covers core analysis and policy-loading
Python sources plus numerical/runtime versions. Even an unrelated core change may
invalidate evidence. Third-party transitive implementation identity is not yet
supported for promotion. R07-03 must trigger fresh validation when it changes code.
Do not reuse test fixture manifests or manufacture evidence to satisfy the gate.

Manifest fields:

| Fields | Contract |
| --- | --- |
| `schema_version`, `id`, `metric_id`, `taxonomy_type` | Version 1; named manifest and exact subject rule |
| `detector_digest`, `thresholds_digest`, `binding_digest`, `scope_digest` | Four lowercase SHA-256 identities matching the run |
| `status`, `accepted_by`, `accepted_at`, `valid_until` | Accepted, accountable nonempty actor, timezone-aware acceptance not in the future; optional unexpired validity |
| `validation_report`, `validation_report_digest`, `operating_scope` | External evidence reference, SHA-256 and human-readable scope |
| `tuning_sessions`, `validation_sessions` | Unique identifiers, no overlap; validation session list required for acceptance |
| `independent_episodes`, `real_fault_validation`, `combined_policy_validated` | All must be declared true for acceptance |
| `valid_episodes`, `false_blocks`, `fault_episodes`, `detected_faults` | Nonnegative counts; outcomes cannot exceed their denominators |

The initial operating gate requires at least 600 independent valid episodes and
100 real fault episodes. The exact one-sided 95% false-block upper confidence bound
must be at most 0.5%; the recall lower bound must be at least 90%. For illustration,
0/600 false blocks and 96/100 detected faults meet the numerical bounds; 1/600 and
95/100 respectively do not. Counts alone are insufficient without the other
acceptance conditions. Session independence and representative operating scope
require a defensible validation study; adjacent correlated episodes cannot simply
be counted as independent trials.

Kalanos checks declarations, bounds and identities. It does not fetch/authenticate
the external report, authenticate the reviewer, or independently establish labels,
independence or combined-policy performance. These are review responsibilities.
A matching accepted declaration is trusted configuration, not cryptographic proof.
Scope matching covers the declared configuration; it does not automatically verify
the physical robot, task distribution or environment described in `operating_scope`.
Operators must select the matching requirements/binding/policy scope for their data.
The benchmark continues to evaluate detector measurements/severity and uses the
shared configuration resolver; synthetic benchmark output never creates a manifest
or claims calibration-gated eligibility parity.

Validation workflow:

1. Freeze final code/runtime, thresholds, bindings and scope. Run a diagnostic audit
   and capture the expected candidate contexts from report JSON.
2. Tune using designated sessions, then evaluate independent held-out valid and
   real-fault episodes in the named scope. Include the complete combined decision
   policy in the study and record false-block/recall counts and limits.
3. Have the designated reviewer assess evidence and record explicit acceptance in
   the policy manifest, with report reference/digest and validity if appropriate.
4. Grade with that policy and verify matched manifest IDs and resulting consequences.
   A mismatch, revocation, expiry or inadequate evidence must leave review.
5. Repeat validation after identity-changing code/configuration/runtime updates.

## 8. Verification and release acceptance

Automated controls cover:

- Report-only torque coverage, unknown taxonomy, optional/required visual evidence,
  metadata skipping, metric requirements, inventory disclosure and count validation.
- Null/NaN/Inf adjacency, source row maps, split intervals, unknown units, spike
  filter context and whole-episode SNR support.
- All manifest identity mismatches, missing/future/expired/revoked acceptance,
  session overlap, malformed counts, confidence bounds and legacy bypass attempts.
- Default review and explicitly synthetic accepted-block positive controls; stable
  finding IDs, group membership and shared JSON/HTML/terminal/inspect evidence.
- Operational exceptions, partial completion, preserved report output and exit 2.
- Identified and unidentified comparisons, changed inputs/configurations, unknown
  plugins, legacy reports, protected input files, source mutation and symlink refusal.
- Profile commands, Python exports, module entry point and installed-wheel workflows.

Local verification results and clean-apply evidence are recorded in the accompanying
`R07-05-07-verification.md`. Tests exercise mechanics; synthetic accepted manifests
are test data only. The dedicated real schema-6.3 fixture verifies compatibility,
not correctness of a fresh public-data audit.

Before publishing, rerun public towel/battery and representative time-series audits
with pinned source revisions and configuration, review changed counts and reasons,
and run supported-Python CI. Coordinate downstream publisher/Action consumers in
their own repositories. Do not claim visual coverage, measured acquisition timing
without provenance, or accepted statistical blocking without real reviewed evidence.
The previously accepted empty-index P2 is not expanded in this patch.

Review the combined change in one PR if desired. No commit, push, package publication
or release is performed by preparing this patch. Keep the three slice boundaries
in review notes even when applying and releasing them together.
