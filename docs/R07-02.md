# R07-02 — Scoped channel bindings and shared configuration

Prepared 29 September 2026. Implementation baseline: `release/0.7.0` at
`225558c12c19e6776adea50e181b59f758e1a7af` (merged round-4 corrections).

## 1. Outcome and release boundary

R07-02 gives grading and benchmarking the same interpretation of the recording.
It makes channel meaning, mapping provenance, validation evidence and evaluation
requirements explicit. A vector containing positions, effort and discrete
commands must not be treated as one homogeneous physical signal.

The accompanying patch implements the resolver, connects it to both public
entry points, adds typed views without changing source indices, exposes binding
evidence in reports, and adds regression controls and README documentation.
It does not change statistical blocking thresholds or claim parity with any other audit tool.

The following remain separately sequenced:

- R07-03: SNR applicability/absolute-floor policy, consequences and sufficiency.
- R07-04: clock provenance, original row order and observability. No timestamp-sort
  change is included here.
- R07-05: capability coverage denominators and localized finding support.
- R07-07: calibration manifests and statistical-blocker promotion, including
  detector/threshold/binding/scope matching.
- R07-08/09: complete consumer presentation, rollout and public-data re-audits.
- Deeper diagnostics are now included in 0.7.0; see [the current contract](DIAGNOSTICS-0.7.0.md) for timing, visual, motion and cohort scope.

The accepted empty-episode-index API issue remains a deferred P2. This patch does
not change that prioritization or the public API's `NothingToGrade` guard.

## 3. Contract decisions

### 3.1 Permanent sidecars and two levels of precedence

Existing mapping files and `kalanos-map.yaml` sidecars remain supported. There is
no deprecation, automatic rewrite or automatic migration into a bundle.

At the whole-feature level, retain:

`argument > explicit map file > bundle features > automatic sidecar > source inference`

Conflicting assertions at the same priority are errors even if a higher-priority
assertion would otherwise hide them. Lower-priority conflicts remain visible.
`--no-sidecar` disables automatic discovery only.

Whole-feature mappings are compatibility defaults. A specific channel binding
retains its meaning even when a higher-priority whole-feature flag disagrees.
Both values and the resolution reason are recorded on the channel. A partly
recognized declared vector retains unknown members under a whole-feature override.
To resolve such a member, supply its explicit per-channel binding.

This is intentional specificity, not a reversal of the feature precedence table.
For example, `--map mixed=proprio.joint_position` cannot turn a bound effort member
of `mixed` into a position channel.

### 3.2 Selectors and source identity

- `feature` matches the adapter's original `source_field` exactly.
- `index` is a zero-based source member index. LeRobot records it from manifest
  order; other multichannel streams record their adapter channel order.
- A scalar channel without a vector index uses `null`. A one-member LeRobot
  feature uses `0`.
- Optional `name` is an expected source-name assertion. A mismatch is an error.
  It is not a replacement display label.
- Optional `source_identity` restricts the selector to an exact resolved dataset
  root/file URI. Without it, the selector can match across the run.
- Duplicate selectors, a global/scoped overlap on the same input, unmatched
  selectors, negative indices and unknown taxonomy keys are configuration errors.

Source scope is a URI/path scope, not a content hash. Remote sources should use
pinned revisions. For local sources, an unchanged path does not prove unchanged
bytes. R07-01 source-evidence completeness and R07-07 promotion evidence remain
separate. No cross-export/reindex identity guarantee is invented.

### 3.3 Meaning is separated into properties

| Property | Example | Why it is separate |
| --- | --- | --- |
| actuator | gripper | Device kind does not imply position |
| quantity | effort, position, binary | Determines what the values represent |
| representation | continuous, discrete, angle | A switch is not a smooth signal |
| unit | rad, Nm | Unit declarations do not prove calibrated scale |
| command | absolute, delta, rate, none, unknown | Delta commands cannot be treated as absolute positions |
| device | left, right | Keeps bimanual channels distinguishable |
| frame/sign | named frame; -1 or 1 | Preserves declared conventions |
| alignment/calibration_transform | reference string | Records a declaration; this patch does not apply transforms |
| limits | finite increasing pair | Declared limits differ from observed extrema |
| noise_reference | reference string | Names relevant evidence; not a detector calibration manifest |

Unknown is explicit. An override does not automatically validate identity, units
or limits. Input `origin`/`status` fields cannot make a bundle assertion appear
producer-declared or validated: the resolver derives those outcomes.

### 3.4 Validation belongs to a property and a scope

A validation record contains `property`, `value`, `validator`, `evidence`, `scope`
and optional `capability`. Validator and evidence cannot be blank.

The record is active only if its value matches the resolved property and its
scope matches the resolved source URI. Identity validation uses
`"<feature>[<index>]"`, for example `"observation.state[0]"`.

An example attestation for a unit is:

```yaml
validations:
  - property: unit
    value: rad
    validator: acquisition-owner
    evidence: acquisition-config-v3
    scope: /absolute/path/to/the/dataset
    capability: derivatives
```

Derivative readiness also requires matching identity and quantity evidence.
Unit evidence alone does not validate the whole channel. Evidence scoped to
derivatives does not validate physical limits or noise claims.

Changing a resolved channel property invalidates the channel's prior records
conservatively. Invalidated records remain in the report. Newly supplied evidence
can establish the replacement interpretation. Evidence references are accountable
attestations; this patch does not fetch, authenticate or independently verify
external documents.

## 4. Runtime flow and required code changes

1. Resolve the source and enforce existing environment/API budgets.
2. Load policy, dictionary and bundle using `prepare_configuration()`.
3. Merge legacy feature mappings with the existing strict conflict rules.
4. Apply supported bundle resource caps and record effective execution identity.
5. Read adapter metadata/episodes at the selected tier.
6. Resolve each channel from source field/index, inferred semantics and explicit
   declarations. Record origins, conflicts and validation outcomes.
7. Create homogeneous typed views. Preserve source field, source index,
   timestamps and values. The original source stream is not mutated.
8. Grade these views or feed the identical views to the benchmark injector.
9. Hash the actual resolved channel records, excluding display names, payload
   values, episode repetition and payload-dependent prerequisite readiness.
10. Serialize bindings even when payload grading is skipped, and evaluate
    requirements without treating an unavailable capability as a pass.

happens in the binding resolver and is labelled inferred. Explicit quantity
information must survive a device name such as `left_gripper`.

## 5. Requirements, capabilities and limits

The default remains `numeric-core-v1` at the standard tier. It retains the existing
numeric-payload and integrity-family requirements. Missing physical validation
does not by itself make generic numeric inspection unavailable.

`vision-imitation-v1` adds `video_quality`. That capability is unimplemented in
this patch and therefore produces an unknown reason. A confirmed block still
takes precedence under the existing eligibility truth table.

Capability prerequisite records have `ready` and `reasons`; they do not say a
detector ran or passed:

| Capability | Prerequisites / effect |
| --- | --- |
| numeric | Available numeric frame column; no calibrated physical unit required |
| derivatives | Numeric payload; scoped identity, quantity and unit evidence; kinematic quantity; continuous/angle representation; compatible command semantics |
| limits | Numeric payload and physical evidence plus validated declared limits; does not implement a limit detector |
| noise | Numeric payload and physical evidence plus matching noise-reference evidence; reward/discrete semantics excluded from this prerequisite |

The metric registry supports `Requires(capabilities=[...])`. Registered jerk and
chatter calculations use the derivative prerequisite. Existing SNR policy and
absolute thresholds are deliberately unchanged for R07-03. Physical limit/noise
prerequisite readiness alone cannot satisfy a required detector capability.

Only numeric inspection is recognized as a completed capability by this slice's
new `required_capabilities` check. Requiring any future capability yields unknown
rather than substituting its prerequisite record for execution evidence.

`metadata`, `standard` and `full` do not change requirements. No new decoder,
sampling strategy or cache is implied by full tier. Metadata benchmarking injects
no payload defects and explains why.

Supported `execution.limits` keys are nonnegative integer/null `max_bytes` and
`max_files`. Effective remote caps are the minimum of the existing environment/API
budget and the bundle cap. A bundle cannot silently lift another budget. Effective
budgets participate in execution identity. Unknown keys are rejected. Existing
local-source behavior remains unrestricted by these remote-source budgets.

Explicit Python `policy=` overrides a bundle policy and is labelled argument
origin. Otherwise a bundle policy path is relative to its YAML file; a relative
path in an in-memory bundle remains an error. Grading and benchmarking use the
same loader and policy precedence.

## 7. README and consumer acceptance

The README update must explain:

1. Working per-channel YAML and grade/benchmark invocations.
2. Permanent sidecars and feature-vs-channel specificity.
3. Source indices, expected names and exact source scoping.
4. Per-property validation, invalidation and accountable evidence references.
5. Numeric vs vision requirements and tier independence.
6. Where computed and ungraded bindings appear in JSON.
7. Prerequisite readiness versus detector execution and calibration approval.
8. Enforced resource budgets, explicit policy precedence and unsupported features.

Consumers must read `channels[].channel.binding` for graded channels and
`declared_channels[].binding` when grading did not occur. They must not interpret
typed-view count as physical sensor count. Old raw reports are not rewritten or
retroactively relabelled. External Worker/converter deployment is not included in
this repository patch.
