# R07-04 — Clock provenance, source order and timing observability

Prepared 29 September 2026. Patch baseline: `release/0.7.0` at
`ecb24ec5a9417133c10243bcbe09d90103a3acdd`, the merged R07-02 implementation.

## 1. Sequencing decision

**Implement R07-04 next. It does not depend on R07-03.**

R07-01 supplies the clock/order models and R07-02 preserves source identity and
channel interpretation through typed views. Both are merged. Clock provenance
and row-order correctness can therefore proceed while SNR applicability and
statistical decision policy remain separately scheduled.

Recommended sequence: R07-04 → R07-03 → R07-05 → remaining calibration and release
work. R07-05 can consume the explicit clock evidence produced here; R07-07 still
owns calibration-manifest matching and statistical-blocker promotion.

The empty-episode-index API issue remains the previously accepted P2. This patch
does not change its priority or the `NothingToGrade` guard.

## 2. Outcome

A report must distinguish a recording's timeline from verified sensor capture
timing. Grading must preserve the timestamp defects it is meant to expose.

The patch:

1. Preserves recorded row order in LeRobot, tabular and MCAP readers.
2. Populates clock provenance and carries it into report JSON.
3. Retains native ticks for precise adjacent-gap calculations.
4. Separates recorded cadence diagnostics from acquisition timing checks.
5. Preserves generated-clock provenance when gaps or synthetic defects exist.
6. Makes invalid timestamps and source-row addresses explicit in timing evidence.
7. Updates benchmark injectors, adapter contracts, tests and documentation.

No threshold value or statistical promotion rule changes. Three recorded-axis
metrics gain empty default-policy entries so their measurements remain report-only.
Existing scores can still change because unsupported acquisition checks now
abstain, and source-order defects are no longer concealed by sorting.

## 3. Why these decisions matter

| Recording/use case | Previous risk | R07-04 behavior |
| --- | --- | --- |
| Robot rows have times `0.00, 0.04, 0.02, 0.06` | Sorting removes the backwards step before inspection | Preserve row/value pairing; report the offending source sample |
| Exporter writes `frame_index / 50` | A generated clock may appear perfectly measured | Report a 50 Hz recorded cadence; acquisition metrics abstain |
| One frame disappears from that export | Skipped frame indices remove the generated label | Retain inferred-generation provenance and report a recorded-grid gap estimate |
| Documented hardware capture clock is exactly uniform | Uniformity heuristic refuses legitimate timing evidence | Measure it when producer capture semantics are explicit |
| Unknown timestamp column is jittery | Jitter is mistaken for evidence of capture origin | Show recorded interval spread without promoting origin |
| MCAP message contains `header.stamp` | Header presence is treated as capture evidence | Preserve its values with unknown origin unless a producer contract establishes more |
| Robot logs time since boot | Unix epoch is silently assumed | Leave epoch unknown unless established; units alone do not define an epoch |
| Epoch-sized nanosecond ticks differ by 1 ns | Float conversion collapses distinct ticks into repeats | Subtract retained integers before scaling to seconds |
| A timestamp is null, NaN or infinite | Dropping it invents adjacency and shifts finding indices | Break adjacency, disclose invalid count and retain source row addresses |
| HDF5 has a badly ordered `timestamps` dataset | Reader replaces the bad clock with a clean generated grid | Preserve the recorded axis for audit |

## 4. Contract

### 4.1 Clock origin and evidence

Origins remain `capture`, `receive`, `publish`, `log`, `presentation`, `generated`,
`simulation` and `unknown`. Evidence remains `producer`, `adapter`, `inferred` or
`none`. These fields answer different questions: what the timestamp means and
how that meaning is known.

`ClockInfo` records source field, native unit/dtype, known epoch/domain and
ordered transforms. `tick_period_s` is an optional positive finite seconds-per-tick
factor for a generated counter or another explicitly scaled tick source.

Acquisition metrics require both:

```text
origin == capture
origin_evidence == producer
```

This qualifies provenance; the individual metric must also have sufficient valid
samples, known seconds, positive adjacent gaps and regular sampling. A clock can
have established capture origin while its timestamps are too damaged to measure.

A legacy `Clock.CAPTURE` label now migrates as inferred capture, not producer
proof. Explicit `ClockInfo` controls the compatibility `clock` enum. A legacy
reconstructed label continues to migrate as inferred generation.

Producer evidence is an adapter's accountable interpretation of a producer schema
or acquisition contract. This patch does not authenticate that contract. Generic
built-in readers make no automatic capture promotion from channel bundles,
timestamp names, jitter, or header presence. A custom adapter may supply explicit
capture provenance when justified; see `docs/ADAPTERS.md`.

### 4.2 Original order

Built-in readers do not sort sample rows by timestamp. Sorting episode metadata
by episode ID, enumerating files deterministically and sorting source-row indices
to reconstruct an explicitly transformed view are separate operations.

`SourceOrder.preserved` describes retained relative row order. When present,
`original_index[i]` identifies current row `i` in the source stream/table. Indices
must be aligned, unique and nonnegative; a preserved sequence has increasing
indices. Tabular instance partitions retain their original table-row addresses.
LeRobot findings use episode-local sample addresses.

A third-party transformed stream sets `preserved=False` and supplies its row map.
Timing checks restore source order using that map. Without a map they abstain.
No sorting is applied to the input payload as a repair.

### 4.3 Native ticks and invalid values

`Stream.native_timestamps` retains numeric source ticks aligned with canonical
`timestamps` and payload rows. It is an internal analysis field, not an array
copied into every report stream. Report JSON carries clock metadata and addresses.

Integer ticks are subtracted before conversion to seconds, avoiding epoch rounding
and unsigned underflow on backwards steps. Unknown units still permit exact
ordering checks, but cannot produce a seconds-based cadence measurement.

Null, NaN and infinite timestamps break adjacency. For `[0, null, 0.04]`, there is
no observed adjacent gap spanning the null. Whole-stream cadence estimates
abstain on an invalid axis. Structural checks may still count valid adjacent
pairs elsewhere and disclose the excluded timestamps.

## 5. Adapter behavior

| Adapter/path | Implementation |
| --- | --- |
| LeRobot v2/v3 | Remove sample timestamp sorts; retain original timestamp column and dtype; attach episode clock metadata to numeric and camera metadata streams |
| LeRobot generation inference | Match recorded time to frame index/rate within source precision; gaps/reordering do not disprove generation; null/nonfinite stamps cannot establish a match |
| CSV/delimited/JSON/JSONL | Preserve rows through normalization and instance partitioning; retain native ticks and original table-row indices; origin remains unknown |
| HDF5 recorded axis | Retain a compatible time-named numeric dataset even when it contains backwards/nonfinite values; disclose unit inference and unknown origin |
| HDF5 fallback | Mark index/rate generation as adapter evidence, retain counter ticks and tick period; a regular generated grid remains non-acquisition |
| MCAP | Read file/message order with `log_time_order=False`; remove per-topic sorting; retain chosen integer ticks and conversions |
| Camera/video metadata | Keep the clock actually read from metadata; do not relabel metadata stamps as decoded presentation timestamps |

MCAP selection is per topic, never per row: a complete nonzero header column wins;
otherwise use a complete nonzero publish column distinguishable from log time;
otherwise use log time. A copied publish column cannot establish a separate
publish clock. Header origin remains unknown; publish and log fields retain their
respective meanings. No physical clock domain or epoch is invented.

This follows the format's distinction between recorded time and published time,
and its allowance for producer-defined epochs. [MCAP specification](https://mcap.dev/spec#message-op0x05),
[timestamp representation](https://mcap.dev/spec#timestamp).

HDF5 time-field selection and tabular time-column/unit inference remain format
heuristics. Their results are not evidence of capture origin. A schema discovery
refusal stays explicit; this patch does not guarantee discovery of every damaged
or ambiguously named time column.

## 6. Metric contract

| Metric | Claim | Prerequisites | Default decision behavior |
| --- | --- | --- | --- |
| `monotonic_violations` | Adjacent repeats/backwards steps in source order | Recoverable order; at least one finite adjacent pair | Existing policy retained |
| `recorded_hz` | Median cadence of recorded axis | Known seconds; complete increasing regular axis; ≥2 samples | Report-only |
| `recorded_dt_spread_ms` | Spread of recorded adjacent intervals | Same; ≥5 samples | Report-only |
| `recorded_drop_estimate` | Estimated holes relative to recorded median cadence | Same; ≥2 samples | Report-only |
| `effective_hz` | Capture cadence | Recorded-rate prerequisites plus producer capture evidence | Existing rate policy retained |
| `dt_jitter_ms` | Capture interval spread | Recorded-spread prerequisites plus producer capture evidence | Existing jitter policy retained |
| `drop_rate` | Missing-sample estimate on a capture timebase | Recorded-drop prerequisites plus producer capture evidence | Existing drop policy retained |

The dropout estimate remains `(expected - observed) / expected`, clamped below at
zero, with `expected = duration / median_gap + 1`. It is an estimate against the
observed cadence, not a verified hardware frame-loss count. The evidence states
the denominator and estimate status.

Evidence includes origin, origin evidence, provenance-based acquisition
observability, measurement scope, sample/gap counts and invalid-timestamp counts.
Ordering evidence includes repeated/backwards counts, first offending source row
and up to 100 offending indices with an explicit truncation flag. Counts remain
complete when the address list is truncated.

These evidence fields prepare R07-05; they do not implement its coverage ledger.
The existing unavailable-capability behavior remains conservative. No new
`acquisition_timing` requirement preset is introduced here.

## 8. Tests and acceptance criteria

The dedicated test module contains 50 parameterized acceptance cases.

| Control | Expected result |
| --- | --- |
| All eight origins with producer evidence | Only capture origin can enable acquisition metrics |
| Capture with none/inferred/adapter evidence | Acquisition metrics abstain |
| Exactly uniform declared capture clock | Measured rate and zero jitter are permitted |
| Jittery unknown clock | Recorded spread available; acquisition remains unavailable |
| Generated grid with a missing row | Recorded gap estimate available; acquisition unavailable |
| Null/NaN/±Inf row | No bridge across invalid row; original offender addresses preserved |
| Epoch-sized unsigned nanoseconds | No false repeat or unsigned-underflow backwards step |
| Unknown-unit integer ticks | Exact ordering remains available; Hz unavailable |
| Sorted view with row map | Original backwards step still detected |
| Sorted view without row map | Explicit abstention |
| Invalid/duplicate/negative/misaligned maps and native ticks | Validation error |
| Legacy capture and explicit clock metadata | Legacy label cannot supply producer evidence; explicit metadata controls compatibility |
| Raw LeRobot v2/v3 reordered fixtures at standard and metadata tiers | Original rows/values retained and backwards step detected; no video decode |
| LeRobot null/NaN/Inf timestamps | Fault retained and generation not inferred |
| CSV reordered rows | Source addresses and payload values stay aligned |
| HDF5 generated, backwards and nonfinite axes | Correct provenance; recorded faults never replaced with a clean grid |
| MCAP header/publish/log fixtures with out-of-order writes | File order retained; origins distinguished; epoch left unknown |
| Report JSON round trip and grade/benchmark parity | Provenance survives; configuration/binding scope remains consistent |
| Drop/repeat/jitter/drift injectors with native ticks | Injected defects remain visible; no stale native array or generated-to-capture promotion |

The existing metric contract suite also tests discrimination of each new
recorded-axis metric against its corresponding injected defect. Existing R07-02,
inventory, refusal, eligibility and CLI controls remain in the full suite.

Test updates are behavior changes, not removal of correctness checks: adapter
contracts continue to reject malformed shapes, bad row maps and mismatched
payloads. Format-specific fixtures establish that source defects are preserved.

## 9. README and migration acceptance

README changes explain the new JSON fields, clock categories, preserved source
order, recorded versus acquisition metrics, invalid timestamps, MCAP selection,
and expected score changes. Adapter documentation shows explicit producer capture
metadata and explains the responsibility behind that declaration.

Consumers must distinguish `measurement_scope=recorded_timeline` from
`measurement_scope=acquisition`. Do not rename recorded spread to capture jitter,
or convert an unavailable acquisition metric to zero. `clock_info=null` in an old
report remains missing provenance, not evidence of capture.

Native ticks are intentionally omitted from report JSON. The report supplies
source paths/fields, indices and transformation metadata for inspection against
the original recording. Existing saved reports are not rewritten.

## 10. Boundaries and remaining work

- R07-03 still owns SNR applicability and decision-policy changes.
- R07-05 still owns availability/applicability coverage accounting and full
  interval-support models. This patch supplies bounded sample addresses only.
- R07-07 still owns calibration manifests and promotion enforcement.
- Cross-stream alignment, latency, skew, drift fitting and synchronization checks
  are later work. Equal units, epochs or generated domains do not prove alignment.
- Media PTS extraction and decoding are not added. The presentation origin is
  supported by the model/negative controls; LeRobot camera metadata is labelled
  as the metadata clock actually inspected.
- Timing precision fixes apply to these timing metrics. They do not rewrite all
  downstream motion calculations around native ticks.
- No input repair, resampling, export or training-reader modification is included.
- Public TOTO/towel/battery reports and deployed consumers require separate
  re-audits before their QA rows or published results are closed.
